This is the 1.62.0 release of Agones.

This release introduces the new RollingUpdateSurge alpha feature, includes a breaking change requiring a trailing % for Fleet maxSurge and maxUnavailable percentage values, and focuses on improving GameServer controller reliability, port allocation, and Fleet autoscaler behavior. Key updates include applying maxSurge during Fleet rolling updates that hold Allocated GameServers, preventing rate-limiter exhaustion during informer resynchronization, fixing duplicate host ports allocated to a single GameServer, fixing GameServer health status reporting for container crashes when the SidecarContainers feature gate is enabled, correcting replica reporting when autoscaling is declined, and improving Fleet autoscaler error diagnostics. Together, these changes make Fleet rolling updates more predictable, strengthen GameServer lifecycle management, and improve troubleshooting.

- **Fleet Rolling Update Percentage Validation:** Fleet maxSurge and maxUnavailable percentage values now require a trailing %, so a bare numeric string such as 25 that was previously read as 25% is now rejected. This aligns Fleet validation with Kubernetes Deployments and the existing FleetAutoscaler bufferSize validation, so update any Fleet manifests that use bare numeric strings to 25% before upgrading.

- **Improved GameServer Controller Reliability:** Fixed rate-limiter exhaustion in the SucceededController, MissingPodController, and HealthController caused by repeated informer resynchronizations. This improves GameServer state transitions, preventing servers from remaining stuck in Allocated or failing to transition to Unhealthy due to controller queue backlogs.

- **Fix GameServer Health Status:** With the SidecarContainers feature gate enabled, fixed an issue where GameServers were not marked Unhealthy when their containers crashed before reaching Ready. This ensures accurate health status reporting and improves reliability.

- **Fix Fleet Autoscaler Replica Reporting:** Fixed an issue where the Fleet autoscaler returned an incorrect replica count when a webhook responded with scale: false. The fix ensures the configured replica count from the Fleet specification is returned correctly.

- **Improve Fleet Autoscaler Error Reporting:** Improved AutoScalingFleetError events to include the Fleet name and target replica count. This makes autoscaling failures easier to identify and troubleshoot.

- **Fix Autoscaler Test Reliability:** Fixed TestListAutoscalerWithSDKMethods to make it independent of resource deletion order. This improves test reliability and reduces flaky test failures.
