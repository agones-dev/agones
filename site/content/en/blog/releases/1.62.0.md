This is the 1.62.0 release of Agones.

This release introduces the new RollingUpdateSurge alpha feature (disabled by default), which applies maxSurge during Fleet rolling updates that hold Allocated GameServers, includes a breaking change requiring a trailing % for Fleet maxSurge and maxUnavailable percentage values, makes Counts and Lists always on, and focuses on improving GameServer controller reliability, port allocation, and Fleet autoscaler behavior. Key updates include preventing rate-limiter exhaustion during informer resynchronization, fixing duplicate host ports allocated to a single GameServer, fixing GameServer health status reporting for container crashes when the SidecarContainers feature gate is enabled, correcting replica reporting when autoscaling is declined, improving Fleet autoscaler error diagnostics, and fixing Unreal SDK compatibility with Unreal Engine 5.8. Together, these changes strengthen GameServer lifecycle management and improve troubleshooting.

- **Fleet Rolling Update Percentage Validation:** Fleet maxSurge and maxUnavailable percentage values now require a trailing %. A bare numeric string such as "25", previously read as 25%, is now rejected at validation. Fleets that are already stored with a bare numeric string are not re-validated, so their rolling updates will fail in the Fleet controller with an "error parsing MaxSurge/MaxUnavailable value" error until the field is changed to "25%" (or an integer such as 25). Update affected Fleets before or immediately after upgrading.

- **Counts and Lists Can No Longer Be Turned Off:** Removed the CountsAndLists feature gate checks from API validation, controllers, allocation, the Fleet autoscaler, metrics, and the SDK server. This means setting the CountsAndLists feature gate to false no longer disables Counts and Lists, and the feature is always on.

- **Improved GameServer Controller Reliability:** Fixed rate-limiter exhaustion in the SucceededController, MissingPodController, and HealthController caused by repeated informer resynchronizations. This improves GameServer state transitions, preventing servers from remaining stuck in Allocated or failing to transition to Unhealthy due to controller queue backlogs.

- **Fix Duplicate Host Port Allocation:** Fixed an issue where a GameServer with multiple ports could be allocated the same host port more than once, producing an invalid Pod. All of a GameServer's ports are now allocated from a single node, and port requests that exceed a port range's capacity move the GameServer to the Error state instead of retrying indefinitely.

- **Fix GameServer Health Status:** With the SidecarContainers feature gate enabled, fixed an issue where GameServers were not marked Unhealthy when their containers crashed before reaching Ready. This ensures accurate health status reporting and improves reliability.

- **Fix Fleet Autoscaler Replica Reporting:** Fixed an issue where the Fleet autoscaler returned an incorrect replica count when a webhook responded with scale: false. The fix ensures the configured replica count from the Fleet specification is returned correctly.

- **Improve Fleet Autoscaler Error Reporting:** Improved AutoScalingFleetError events to include the Fleet name and target replica count. This makes autoscaling failures easier to identify and troubleshoot.

- **Unreal SDK UE 5.8 Compatibility:** Fixed Unreal SDK compatibility with Unreal Engine 5.8 by updating how GameServer annotation, label, and counter keys are read from JSON. This lets Unreal Engine 5.8 projects use the Agones Unreal SDK.
